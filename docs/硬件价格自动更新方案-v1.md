# 硬件价格自动更新方案 v1

## 1. 目标

为 AI 配置生成提供可持续更新的硬件价格数据，减少首版价格库建立后的人工维护工作。

核心规则：

- 价格更新时间在 7 天内时，AI 直接使用数据库中的价格。
- 价格更新时间超过 7 天时，系统触发查价。
- 查到的新价格通过来源、型号和合理区间校验后，才能同步到价格数据库。
- 查价失败或新价格异常时，保留旧价格，不能清空价格或写入 0 元。

## 2. 方案边界

### 2.1 全新配件

- 全新配件只选择一个电商平台作为价格来源，降低系统复杂度和平台风控风险。
- 每个配件由管理员提供具体商品链接，不由 AI 全网搜索商品。
- 商品链接应尽量指向明确的 SKU，避免同一商品页中的容量、颜色、套装或版本差异导致误取价格。
- 系统从商品页读取当前价格、库存状态和 SKU 信息。
- 通过合理价格区间校验后，价格才可以同步到数据库。

### 2.2 二手配件

- 二手配件使用管理员提供的关键词在闲鱼搜索。
- 系统收集一定数量的有效样本，并排除坏件、维修件、仅包装、缺件、配件、批发、求购和明显异常低价。
- 二手价格不取绝对最低价，优先使用过滤后样本的中位价，或第 25 百分位的低位参考价。
- 二手价格与全新价格分开存储和展示。

## 3. 查价流程

### 3.1 AI 生成配置

1. AI 根据用户预算、用途和偏好，从维护中的硬件目录选择电脑八大件。
2. 系统查询每个配件的当前价格和最后更新时间。
3. 价格在 7 天有效期内时，直接用于预算计算。
4. 价格超过 7 天时，创建价格刷新任务。
5. 刷新成功且校验通过时，更新数据库并使用新价格。
6. 刷新超时、页面受限或校验失败时，继续使用旧价格，并将价格标记为过期或待复核。

### 3.2 全新配件刷新

```text
读取固定商品链接
-> 获取当前 SKU、售价和库存状态
-> 校验商品与目标配件是否一致
-> 校验价格是否在合理区间内
-> 校验价格波动是否异常
-> 通过：写入报价历史并更新当前价格
-> 不通过：保留旧价格并标记待复核
```

### 3.3 二手配件刷新

```text
使用关键词搜索闲鱼
-> 收集候选商品
-> 校验标题和目标型号
-> 排除异常商品和无效价格
-> 应用合理价格区间
-> 计算中位价或低位参考价
-> 写入报价历史并更新二手参考价
```

## 4. 刷新方式

查价应由后端价格刷新任务执行，不应让 AI 模型直接连接数据库或在用户请求中无限等待平台响应。

推荐行为：

- 用户请求只负责检查价格是否过期并触发任务。
- 后台队列按顺序、低频刷新过期价格。
- 可以为刷新设置较短等待时间；任务未及时完成时先使用旧价格。
- 同一个配件在刷新中时，不重复创建任务。
- 同一个配件在 7 天有效期内，不重复访问平台。
- 热门配件可以保持 7 天有效期，冷门配件后续可根据实际访问量延长有效期。

## 5. 数据模型建议

### 5.1 价格来源

`component_price_source`

- `component_id`：配件 ID。
- `condition`：`new` 或 `used`。
- `platform`：价格来源平台。
- `product_url`：全新配件的固定商品链接。
- `search_keyword`：二手配件的闲鱼搜索关键词。
- `expected_sku_text`：全新商品期望匹配的 SKU 描述。
- `min_allowed_price`：允许自动写入的最低价格。
- `max_allowed_price`：允许自动写入的最高价格。
- `enabled`：该来源是否启用。

### 5.2 当前价格

`component_price_current`

- `component_id`：配件 ID。
- `condition`：`new` 或 `used`。
- `selected_price`：当前使用的参考价格。
- `selected_platform`：当前价格来源平台。
- `selected_source_url`：当前价格对应的商品或搜索结果链接。
- `selected_at`：当前价格采集时间。
- `last_checked_at`：最近一次尝试查价的时间。
- `confidence`：`high`、`medium` 或 `low`。
- `status`：`fresh`、`stale`、`refreshing`、`refresh_failed` 或 `needs_review`。

### 5.3 报价历史

`component_price_quote`

- `component_id`：配件 ID。
- `condition`：`new` 或 `used`。
- `platform`：来源平台。
- `observed_price`：本次观测价格。
- `title`：商品标题。
- `sku_text`：本次读取到的 SKU 描述。
- `source_url`：来源链接。
- `observed_at`：采集时间。
- `status`：`accepted`、`rejected` 或 `failed`。
- `reject_reason`：拒绝或失败原因。

## 6. 自动写入规则

新价格只有同时满足以下条件才能覆盖当前价格：

1. 来源与该配件配置的来源一致。
2. 商品标题或 SKU 与目标配件匹配。
3. 商品处于可购买状态，价格不是定金、预售价或配件价格。
4. 价格位于管理员设置的合理区间内。
5. 相比旧价格没有出现超出阈值的异常波动。
6. 页面没有出现验证码、登录失效、访问受限或解析不完整。

任一条件不满足时：

- 不覆盖当前价格。
- 保留本次失败或拒绝记录。
- 将状态设为 `refresh_failed` 或 `needs_review`。
- AI 继续使用旧价格，并在需要时提示价格可能已过期。

## 7. 平台风控处理

7 天缓存只能降低访问频率，不能保证永远不触发平台风控。因此系统必须具备以下保护：

- 单平台、固定商品链接、低频刷新。
- 所有刷新任务进入后端队列，不并发集中访问平台。
- 遇到登录、验证码、滑块或访问限制时立即停止该次刷新。
- 不绕过验证码，不使用代理池、指纹伪装或普通账号轮换来规避平台限制。
- 不通过注册多个普通账号进行流量分摊或绕过单账号限制。
- 优先评估平台官方开放接口、联盟接口或其他明确允许的价格数据渠道。
- 查价失败时保留旧数据，确保平台不可用不会阻断 AI 配置功能。

## 8. AI 与规则系统的职责

AI 可以负责：

- 根据用户需求选择硬件目录中的配件。
- 辅助识别商品标题、SKU 和二手商品描述。
- 解释价格是否过期或为什么暂时使用旧价格。

规则系统负责：

- 判断价格是否超过 7 天。
- 调度和限速价格刷新任务。
- 校验平台、型号、SKU、价格区间和价格波动。
- 决定新价格能否写入生产数据库。
- 记录报价历史、失败原因和待复核状态。

AI 不应无约束地直接覆盖生产价格数据库。

## 9. 失败降级

| 场景 | 系统行为 |
| --- | --- |
| 价格在 7 天内 | 直接使用当前价格 |
| 价格超过 7 天且刷新成功 | 更新数据库并使用新价格 |
| 商品缺货 | 保留旧价格，标记状态 |
| 商品链接失效 | 保留旧价格，进入待复核 |
| 新价格超出合理区间 | 不更新，进入待复核 |
| 页面要求验证码或登录 | 停止刷新，保留旧价格 |
| 闲鱼有效样本不足 | 不更新二手参考价 |
| 刷新任务超时 | AI 使用旧价格，后台稍后重试 |

## 10. 第一版实施范围

第一版只实现以下能力：

- 人工建立硬件目录和初始价格。
- 全新配件使用单平台固定商品链接。
- 二手配件使用闲鱼关键词。
- 使用 7 天价格有效期。
- 设置每个配件的合理价格区间。
- 后台低频刷新、校验和同步价格。
- 保存报价历史和失败原因。
- 刷新失败时继续使用旧价格。

第一版暂不实现：

- 多平台最低价比较。
- 多账号轮换或账号池。
- 自动绕过登录、验证码和平台风控。
- 无限制实时查价。
- AI 直接写入生产数据库。

## 11. 验收标准

- 7 天内的价格不会触发平台访问。
- 超过 7 天的价格只创建一个刷新任务。
- 合法且位于合理区间内的新价格可以更新数据库。
- 异常价格、错误 SKU 和失效页面不会覆盖旧价格。
- 全新价格和二手价格可以独立更新和查询。
- 平台访问失败不会阻断 AI 配置生成。
- 每一次价格接受、拒绝或失败都有可追溯记录。
