# 自有游戏平均 FPS 估算模型设计

日期：2026-07-15

## 目标

建立一套不依赖 PC-Builds 批量数据的自有游戏性能估算模型。用户选择 CPU、显卡、游戏和分辨率后，App 始终为受支持的硬件和游戏组合返回一个预计平均 FPS。

首版准确度目标：

- 常见硬件组合的平均 FPS 误差目标为 5%～8%。
- 冷门、过旧或刚发布的硬件组合可能达到 10%～15%。
- 该目标只针对平均 FPS，不承诺最低帧、最高帧或 1% Low。

## 用户看到的结果

结果页只显示一个主要数字：

> 预计平均帧率：126 FPS

不显示：

- 最低 FPS、最高 FPS 或 1% Low。
- 置信度。
- 误差范围。
- 数据来源或内部计算过程。

固定说明继续保留：结果是统一测试条件下的估算，实际表现会受游戏版本、驱动、散热、内存和后台程序影响。

## 统一测试条件

所有参考测试和估算必须使用同一套条件：

- 画质：高画质预设。
- 光线追踪：关闭。
- 分辨率：1080p、2K、4K。
- NVIDIA RTX：游戏支持时使用 DLSS 质量档。
- AMD RX：游戏支持时使用 FSR 质量档。
- GTX 10 系或不支持超分的游戏：使用原生高画质。
- 帧生成：游戏和显卡都支持时开启，否则关闭。
- 首版只使用标准帧生成；RTX 50 系的 3x/4x 多帧生成不纳入首版，避免同一配置因倍率选择不同产生不可比较的结果。

每条参考数据都必须保存游戏版本、驱动版本、超分模式和帧生成状态。测试条件不一致的数据不能放进同一模型。

## 游戏分类

### CPU 型

- 瓦罗兰特
- CS2
- 云顶之弈
- LOL
- 城市：天际线
- 我的世界 Java 版（不使用光影）

这些游戏主要建立“CPU 型号 → 平均 FPS 上限”参考表。测试 CPU 时搭配性能足够的高端显卡，尽量避免显卡先成为瓶颈。

### GPU 型

- 赛博朋克 2077
- 荒野大镖客 2
- 黑神话：悟空
- 地平线 6
- 艾尔登法环

这些游戏主要建立“显卡型号 → 平均 FPS 上限”参考表。测试显卡时搭配性能足够的高端 CPU。艾尔登法环的最终结果不能超过游戏的 60 FPS 限制。

### 混合型

- PUBG
- 三角洲行动
- COD：战区
- GTA 5

这些游戏同时建立 CPU 和显卡参考点，最终结果由两者中较低的性能上限决定。

## 核心计算方法

每款游戏、每个分辨率分别维护 CPU 上限模型和 GPU 上限模型。

计算步骤：

1. 根据用户 CPU，在该游戏和分辨率下计算 CPU 可提供的平均 FPS 上限。
2. 根据用户显卡、超分和帧生成支持情况，计算显卡可提供的平均 FPS 上限。
3. CPU 型、GPU 型和混合型游戏都取两个上限中的较低值，避免只看主要硬件而忽略真实瓶颈。
4. 应用该游戏通过交叉测试得出的保守修正系数。
5. 应用游戏自身的最高帧率限制，并四舍五入为整数。

概念公式：

```text
预计平均 FPS = min(CPU FPS 上限, GPU FPS 上限)
             × 游戏交叉修正系数
```

修正系数不能长期使用统一常数。每款游戏必须用未参与模型拟合的交叉配置计算自己的修正值。参考数据尚少时可以临时使用 0.95，但在发布该游戏前必须用真实交叉测试替换。

## 参考点与插值

不直接测试约 35 万种 CPU、显卡、游戏和分辨率组合，而是测试有代表性的参考点：

- 每代 CPU 覆盖入门、中端和高端代表型号。
- 每代显卡覆盖入门、中端和高端代表型号。
- CPU 型游戏重点增加 CPU 参考点。
- GPU 型游戏重点增加显卡参考点。
- 混合型游戏增加少量 CPU × GPU 交叉组合。

没有直接参考点的硬件，使用同代和相邻性能档位的两个或多个参考点进行插值。超出已测试性能范围时允许外推，以满足“所有受支持组合都返回数字”的产品要求，但外推必须受到以下限制：

- 更强的同类硬件不能得到更低的 FPS。
- 结果不能超过游戏帧率上限。
- CPU 或显卡明显不足时，结果不能超过另一侧的理想上限。
- 外推比例不能超过该硬件相对性能差距所允许的范围。

## 帧生成与超分处理

游戏和硬件能力由单独的能力表控制，不能根据显卡名称临时猜测。

能力表至少记录：

- 是否支持 DLSS 质量档。
- 是否支持 FSR 质量档。
- 是否支持标准帧生成。
- 是否有固定帧率上限。

计算时先确定用户组合实际可用的模式，再选择对应参考点：

- 支持超分和帧生成：使用“质量档超分＋标准帧生成”参考点。
- 支持超分但不支持帧生成：使用“质量档超分、帧生成关闭”参考点。
- 都不支持：使用原生高画质参考点。

不得给不支持帧生成的显卡虚构帧生成收益。

## 数据结构

### 游戏性能配置

每款游戏保存：

- canonical game ID。
- CPU 型、GPU 型或混合型。
- 三种分辨率。
- 画质预设。
- 超分支持情况。
- 帧生成支持情况。
- FPS 上限。
- 当前模型版本。

### 性能参考点

每条参考点保存：

- 游戏 ID。
- CPU ID 和显卡 ID。
- 被测主要硬件类型。
- 分辨率。
- 平均 FPS。
- 超分模式。
- 帧生成模式。
- 游戏版本和驱动版本。
- 测试日期。
- 来源类型和可使用证明。
- 是否用于模型拟合或独立验证。

### 模型参数

每个游戏和分辨率保存：

- CPU 插值参数。
- GPU 插值参数。
- 交叉修正系数。
- 验证样本数量。
- 平均绝对百分比误差。
- 模型更新时间。

这些诊断字段只供后台维护，不在 App 中显示为置信度。

## 数据来源边界

允许使用：

- 自行实测的数据。
- 取得书面授权或商业许可的数据。
- 明确允许再利用的开放许可数据。

不允许使用：

- 绕过访问挑战、验证码或网站限制获取的数据。
- 未确认商业再利用权利的批量第三方数据。
- 无法说明测试条件和硬件组合的数据。

不接收用户上传的性能数据。所有进入模型的参考点都必须先经过人工审核和格式校验。

## 后端数据流

1. 维护人员导入经过审核的参考点文件。
2. 导入器检查硬件 ID、游戏 ID、统一画质条件、平均 FPS 范围和来源说明。
3. 校准任务按游戏和分辨率生成 CPU、GPU 插值参数及交叉修正系数。
4. 验证任务使用保留样本计算误差，保留样本不能参与拟合。
5. API 根据用户硬件能力选择模式，计算 CPU 上限、GPU 上限和最终平均 FPS。
6. iOS 只显示最终平均 FPS 和固定说明。

## API 行为

保留现有 `/v1/perf/estimate` 路径，输入继续使用硬件 catalog ID、分辨率和游戏 ID。

单款游戏返回：

- 游戏 ID。
- 预计平均 FPS。

多款游戏返回逐款预计平均 FPS，并用逐款结果的平均值作为整体平均 FPS。“什么都玩”继续展开为批准的 15 款游戏。

首版不再要求响应包含最低 FPS、最高 FPS、瓶颈百分比或置信度。模型仍会在内部计算 CPU/GPU 哪一侧限制结果，用于估算和调试，但不作为用户结果字段。

## 异常与边界处理

- CPU、显卡或游戏 ID 不在维护目录中：拒绝请求，不为未知型号编造结果。
- 受支持目录内缺少直接参考点：使用受约束外推，仍返回平均 FPS。
- 游戏不支持帧生成：自动关闭帧生成。
- 显卡不支持指定超分：按能力表回退到 FSR 质量档或原生高画质。
- 模型参数损坏或结果超出合理范围：拒绝发布该模型版本，继续使用上一版已验证模型。
- 游戏大版本或渲染管线变化：创建新模型版本，旧数据不直接混入新版本。

## 准确度验收

每个准备发布的游戏和分辨率必须保留至少 20% 的交叉配置作为验证集。验证集不参与参数拟合。

首版发布标准：

- 常见硬件档位的平均绝对百分比误差不高于 8%。
- 不允许通过删除误差较大的验证样本来达标。
- 单调性测试通过：同条件下，更强的 CPU 或显卡不能导致更低的估算 FPS。
- 帧率上限、超分支持和帧生成支持测试通过。

冷门硬件允许高于 8%，但必须包含在离线误差报告中。App 仍只显示平均 FPS，不显示置信度。

## 测试计划

- 游戏分类和能力表单元测试。
- CPU、GPU 插值和受约束外推测试。
- CPU 瓶颈、GPU 瓶颈和混合瓶颈测试。
- DLSS、FSR、帧生成支持与回退测试。
- 艾尔登法环 60 FPS 上限测试。
- 单调性和异常值测试。
- 校准集与验证集隔离测试。
- 平均误差报告测试。
- API 单款、多款、“什么都玩”和未知硬件测试。
- iOS 只显示平均 FPS 的规则测试。
- 完整后端测试和 iPhone 17 模拟器构建。

## 非目标

- 不估算最低帧、最高帧或 1% Low。
- 不显示置信度。
- 不接收用户上传测试数据。
- 不支持光追测试。
- 首版不支持 RTX 50 系 3x/4x 多帧生成。
- 不保证每个冷门硬件组合都达到 8% 以内。
- 不部署或发布来源权利不明确的参考数据。
