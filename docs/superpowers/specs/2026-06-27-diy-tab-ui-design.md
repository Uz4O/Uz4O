# DIY 标签页静态 UI 设计

## 目标

在现有 SwiftUI 应用底部导航中新增 `DIY` 标签页，并按用户提供的参考图还原静态页面。重点保证布局、字号、字重、间距与图片尺寸接近参考图，不实现选配交互或后续业务流程。

## 导航与现有功能

- 底部导航顺序调整为：首页、配置、DIY、我的。
- 新增独立的 `DIYHomeView` 作为 DIY 标签页根页面。
- 保留现有 `DIYBuildView` 及其“游戏性能测试”全屏流程，避免改变首页和配置页已有入口行为。

## 页面结构

页面使用可滚动的白色背景，并在原生底部标签栏上方留出安全间距：

1. 顶部品牌栏：左侧 `UzBox`，右侧铃铛图标。
2. Hero 区：功能眉题、`DIY 自由选配` 标题、两行说明、三条能力说明、黑色圆角按钮、页码圆点，以及右侧电脑硬件组合图。
3. 快捷配件区：CPU、显卡、主板、内存、更多配件五个等宽入口，使用 SF Symbols。
4. 能力区：标题 `DIY 能做什么`，下方两列四张能力卡片，展示总价统计、功耗估算、兼容性检测、瓶颈分析。

## 视觉规则

- 页面主背景使用白色，文字使用黑色与分层灰色。
- 字体采用系统字体；品牌和主标题使用 heavy/bold，正文使用 regular/medium，按参考图比例设置固定字号并允许小屏幕最小缩放。
- Hero 图片使用用户提供的第二张图片，清理其烘焙棋盘背景，使其自然融入白色页面；图片保持原始宽高比。
- 卡片使用低对比度描边、轻微阴影和大圆角；底部标签栏继续沿用项目当前原生 TabView 样式。
- 页面宽度根据屏幕宽度自适应，主要以 iPhone 17 模拟器为视觉校准基准。

## 交互边界

- `开始 DIY`、轮播圆点、五个配件入口及四张能力卡片本次均只展示，不触发导航或状态变化。
- 为静态按钮和入口保留可访问性标签，不新增数据模型、网络请求或选配状态。

## 验证

- 更新底部导航规则测试，验证四个标签及顺序。
- 使用 `xcodebuild` 完成 iPhone 17 模拟器构建。
- 在模拟器中截图，与参考图对照检查标题字重、正文大小、Hero 图片占比、卡片尺寸和底部安全区。
